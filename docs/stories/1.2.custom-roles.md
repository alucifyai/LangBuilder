# Story 1.2: Create and Manage Custom Roles

## Status

Done

## Story

**As an** Admin,
**I want** to define custom roles with specific permissions,
**so that** I can tailor access control to my team's workflows.

## Acceptance Criteria

**@AC1**: Successful creation of a custom role
- Given I am logged in as an Admin
- And I am on the Role Management page
- And I enter role name "Deployer"
- And I select permissions ["deploy_environment","read"]
- When I save the role
- Then a role named "Deployer" is created
- And it is available for assignment to users or groups

**@AC2**: Prevent duplicate role names
- Given I am logged in as an Admin
- And a role "Editor" already exists
- When I try to create another role named "Editor"
- Then I see an error "Role name must be unique"
- And the role is not created

**@AC3**: Edit role and track version
- Given I am logged in as an Admin
- And a role "Deployer" with permissions ["deploy_environment"]
- When I add "read" to the role
- Then the updated role is saved as a new version
- And the audit log shows before and after states

### API Specifications

**Role Management Endpoints (New for This Story)** [Source: architecture/data-models-and-apis.md]

```
GET    /api/v1/roles/             # List all roles
POST   /api/v1/roles/             # Create role (AC: 1, 2)
GET    /api/v1/roles/{role_id}    # Get specific role
PATCH  /api/v1/roles/{role_id}    # Update role (AC: 3)
DELETE /api/v1/roles/{role_id}    # Delete role (with dependency check)
```

**Request/Response Schemas**:

```python
# Request Schema for POST /api/v1/roles/
class RoleCreate(BaseModel):
    name: str                    # Must be unique (AC: 2)
    permissions: list[str]       # List of permission IDs (validated against catalog)

# Request Schema for PATCH /api/v1/roles/{role_id}
class RoleUpdate(BaseModel):
    name: str | None = None      # Optional name update
    permissions: list[str] | None = None  # Optional permission list update

# Response Schema
class RoleResponse(BaseModel):
    id: UUID
    name: str
    permissions: list[str]
    version: int                 # Current version (AC: 3)
    created_at: datetime
    updated_at: datetime
    created_by: UUID | None      # User who created the role
    updated_by: UUID | None      # User who last updated the role
```

**Audit Log Endpoints (New for This Story)**:

```
GET    /api/v1/audit/             # List audit log entries (with filtering)
GET    /api/v1/audit/{audit_id}   # Get specific audit entry
```

**Authorization Requirements**:
- All role management endpoints require admin privileges
- Use RBAC service `check_permission()` with admin check
- Non-admin users should receive HTTP 403 with error "admin_required"

### Technical Constraints

**Database** [Source: architecture/high-level-architecture.md]:
- SQLModel with async support (SQLAlchemy 2.0.38+)
- Use Alembic for database migrations
- Migration naming: `00X_add_Y_table.py` sequential pattern (continue from Story 1.1)
- All datetime fields must use `datetime.now(timezone.utc)` for timezone awareness

**API Standards** [Source: architecture/high-level-architecture.md, architecture/data-models-and-apis.md]:
- FastAPI with async route handlers
- Pydantic v2 for request/response validation
- JWT authentication via `Authorization: Bearer <token>` header
- Admin check using RBAC service before allowing role management operations
- HTTP status codes: 200 (success), 201 (created), 400 (validation error), 403 (forbidden), 404 (not found), 409 (conflict for duplicate name)

**Frontend Standards** [Source: architecture/high-level-architecture.md]:
- React 18.3.1 with functional components and hooks
- TypeScript 5.4.5 in strict mode
- Radix UI components for accessible UI elements
- Tailwind CSS for styling
- Zustand for state management (if needed for role management state)
- Axios 1.7.4 for API calls with proper error handling

**Security Constraints**:
- All role management operations require admin privileges
- Audit logs must be immutable (append-only, no updates/deletes)
- Role deletion must check for active grants to prevent orphaned grants
- Permission IDs must be validated against catalog before role save

**Performance Constraints** [From PRD NFR]:
- Permission evaluation should be ≤100ms p95 (not directly applicable to this story, but keep in mind)
- Audit log queries should use indexed fields (timestamp, actor_id, resource_type)
- Role list should paginate if count exceeds reasonable limit (consider adding pagination)
