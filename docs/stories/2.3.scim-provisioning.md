# Story 2.3: Provision Users and Groups via SSO/SCIM

## Status

Done

## Story

**As an** Admin,
**I want** users and groups to be provisioned automatically from my IdP,
**so that** onboarding and offboarding are automated.

## Acceptance Criteria

**@AC1**: New user provisioned
- Given HR adds "ana@acme.com" to the "Data Team" group in Okta
- When SCIM syncs
- Then a new user "ana@acme.com" is created in LangBuilder
- And the user is assigned the default "Viewer" role in the "Data Team" project

**@AC2**: User de-provisioned
- Given "bob@acme.com" is removed from the IdP
- When SCIM syncs
- Then "bob@acme.com" is disabled in LangBuilder
- And cannot log in

**@AC3**: Group membership drives roles
- Given "Data Team" group is mapped to role "Editor" in Project=PRJ1
- When HR adds "carol@acme.com" to the "Data Team"
- Then Carol automatically gets the "Editor" role in PRJ1

## Implementation Summary

Implemented SCIM 2.0 compliant provisioning:

### Models Created
- `SCIMUser` - Maps IdP users to LangBuilder users
- `SCIMGroup` - Maps IdP groups with role mappings
- `SCIMGroupMembership` - User-group relationships
- `SCIMProvisioningLog` - Audit trail

### API Endpoints (`/api/v1/scim/v2/`)
- `POST /Users` - Create user
- `GET /Users/{id}` - Get user
- `PUT /Users/{id}` - Update user
- `DELETE /Users/{id}` - Deactivate user
- `POST /Groups` - Create group
- `GET /Groups/{id}` - Get group
- `PUT /Groups/{id}` - Update group
- `DELETE /Groups/{id}` - Delete group

### Key Features
- RFC 7643/7644 compliant
- Automatic role assignment via group mapping
- Soft-delete for user deprovisioning
- Complete audit logging
