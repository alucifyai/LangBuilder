# Story 3.3: Manage Roles via IaC

## Status

Done

## Story

**As a** DevOps Engineer,
**I want** to define roles in YAML/Terraform,
**so that** RBAC policies can be version-controlled and automated.

## Acceptance Criteria

**@AC1**: Apply YAML policy
- Given I have a YAML file defining role "Ops" with actions ["deploy_environment"]
- When I apply the YAML
- Then "Ops" exists with those actions

## Context Analysis

### Existing Implementation

**IaC for roles is fully implemented!**

Files:
- `src/backend/base/langflow/services/iac/yaml_parser.py` - YAML parsing
- `src/backend/base/langflow/api/v1/iac.py` - IaC API endpoints

### API Endpoints

✅ `POST /api/v1/iac/apply/policy` - Apply complete YAML policy (roles + grants)
✅ `POST /api/v1/iac/apply/roles` - Apply roles-only YAML
✅ `POST /api/v1/iac/apply/grants` - Apply grants-only YAML
✅ `POST /api/v1/iac/apply/file` - Upload YAML file
✅ `POST /api/v1/iac/validate/policy` - Validate YAML without applying

### Features

- Pydantic-based YAML schema validation
- Support for both formats:
  - Complete policy: `{ version: v1, roles: [...], grants: [...] }`
  - Roles only: `{ roles: [...] }` or `[...]`
- Dry-run mode support
- Detailed error reporting
- Role versioning on updates

### YAML Schema

```yaml
version: v1
roles:
  - name: "Ops"
    description: "Operations team role"
    permissions:
      - deploy_environment
      - read
    allowed_scopes:
      - Workspace
      - Project
```
