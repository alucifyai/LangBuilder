# Story 1.2.1: Role Management Admin UI

## Status

Approved

## Story

**As an** Admin,
**I want** a web interface to manage custom roles,
**so that** I can easily create, edit, and delete roles without using API tools.

## Acceptance Criteria

**@AC1**: Admin can create a custom role through UI
- Given I am logged in as an Admin
- And I am on the Role Management page
- When I click "Create Role" and fill in name "Deployer" and select permissions
- Then the role is created and appears in the role list
- And I see a success message "Role created successfully"

**@AC2**: UI prevents duplicate role names
- Given I am logged in as an Admin
- And I am on the Role Management page
- When I try to create a role with a name that already exists
- And I submit the form
- Then I see an error message "Role name must be unique"
- And the role is not created

**@AC3**: Admin can edit a role and see version history
- Given I am logged in as an Admin
- And I am on the Role Management page
- When I click edit on a role and change its permissions
- And I save the changes
- Then the version number increments
- And I see a success message showing the new version number
- And I can view the audit log showing before/after states

**@AC4**: Admin can view audit log with before/after diff
- Given I am logged in as an Admin
- And I am on the Audit Log page
- When I view role update entries
- Then I can see before/after state differences for each change
- And I can filter by action type, date range, and actor

**@AC5**: Admin cannot delete role with active grants
- Given I am logged in as an Admin
- And a role has active grants assigned to users
- When I attempt to delete the role
- Then I see a warning "Cannot delete role: N active grants exist"
- And the role is not deleted

## Dev Notes

### Backend API Contract

**Story 1.2 Backend Deliverables (Production-Ready):**

All backend endpoints are fully implemented, tested, and production-ready. The frontend can consume these APIs immediately.

**Role Management Endpoints:**

```typescript
// GET /api/v1/roles/
// Response: RolesListResponse
{
  total_count: number;
  roles: [
    {
      id: string;           // UUID
      name: string;
      permissions: string[]; // Array of permission IDs
      version: number;       // Current version
      created_at: string;    // ISO datetime
      updated_at: string;    // ISO datetime
    }
  ];
}

// POST /api/v1/roles/
// Request: RoleCreate
{
  name: string;
  permissions: string[]; // Array of permission IDs
}
// Response: RoleResponse (201 Created)
// Errors:
//   - 403: admin_required (not admin)
//   - 409: Role name must be unique (duplicate name)
//   - 400: Invalid permissions

// PATCH /api/v1/roles/{role_id}
// Request: RoleUpdate
{
  name?: string;         // Optional
  permissions?: string[]; // Optional
}
// Response: RoleResponse (version incremented)
// Errors:
//   - 403: admin_required
//   - 404: Role not found
//   - 409: Role name must be unique
//   - 400: Invalid permissions

// DELETE /api/v1/roles/{role_id}
// Response: { detail: "Role deleted successfully" }
// Errors:
//   - 403: admin_required
//   - 404: Role not found
//   - 409: Cannot delete role: N active grants exist
```

**Audit Log API (Backend Endpoint Needed):**

The backend has `AuditLog` model and CRUD service implemented, but REST API endpoints are not exposed. Frontend implementation requires backend team to add:

```typescript
// GET /api/v1/audit/
// Query params: action?, resource_type?, actor_id?, start_date?, end_date?, skip?, limit?
// Response:
{
  total_count: number;
  logs: [
    {
      id: string;           // UUID
      timestamp: string;     // ISO datetime
      actor_id: string;      // User UUID
      action: string;        // AuditAction enum
      resource_type: string; // "role", "grant", etc.
      resource_id: string;   // Resource UUID
      before_state: object | null; // JSON state before change
      after_state: object | null;  // JSON state after change
      metadata: object | null;     // Additional context

```

### Error Handling Strategy

**HTTP Error Codes:**
- 400: Bad Request - Display error message from `detail` field
- 403: Forbidden - Redirect to login or show "Admin access required"
- 404: Not Found - Display "Resource not found" message
- 409: Conflict - Display specific conflict message (duplicate name, active grants)
- 500: Server Error - Display generic "Something went wrong" message

**Error Message Display:**
- Use `useAlertStore` for toast notifications (existing pattern)
- Success messages: Green toast, auto-dismiss after 3s
- Error messages: Red toast, manual dismiss
- Validation errors: Inline below form fields

**Error Boundary:**
- Wrap role management pages in error boundary
- Display fallback UI on unexpected errors
- Log errors to console (dev) or monitoring service (prod)
